# 115 Cloud 按需分页（实验性源码补丁）

## 行为

网页 `/api/fs/list` 对支持 `driver.PagedReader` 的 115 Cloud 挂载使用独立的分页调用链：

```text
网页 page=N, per_page=S
  -> 检查目录权限
  -> offset=(N-1)*S, limit=S
  -> 独立按页缓存 / 合并同页请求
  -> 115 一次有界列表请求
  -> 当前页隐藏规则与逐对象权限过滤
  -> 返回当前页，不预取下一页、不扫描补满
```

`per_page<=0`（包括 `-1` / 显示全部）对这种挂载改为 50；最大 500。`page_size` 保留为完整列表接口的上游分批大小，不再控制网页分页。普通网页翻页不进入旧 `List` 循环，也不将部分页面当作完整目录交给缓存或索引更新钩子。

冷启动路径可能额外请求挂载根信息、目录路径定位；文件直接链接可能额外做一次最多 50 条的查询。因此“一页一次列表请求”不代表整个导航总共只有一次 HTTP 请求。

配套前端对这类挂载强制手动翻页，即使站点设置为“全部”或“自动加载更多”也不会自动读取下一页。改变排序回到第一页，上游执行排序，不在局部页面中伪装全局排序。换页大小和排序清理旧的网页历史快照。

## API 增量

保留现有响应封装。`fs/list` 增加：

- `source_pagination: true`：内容已经由上游分页，不应二次切页或后台自动遍历。
- `total_exact: false`：没有扫描整个目录计算过滤后的精确数量。
- `has_more`：取决于上游范围，而不是过滤后 `content.length`；隐藏规则可让当前页为空，仍可继续翻页。
- `total` / `filtered_total`：此模式下均为上游原始数量，不是权限过滤后的精确计数。
- `pages_total: 0`：不声明精确可见总页数；配套 UI 显示页码和上/下一页，不显示精确总数。

`fs/get` 同样增加 `source_pagination`，让冷启动导航可以发现能力。

`fs/list` 新增可选 `order_by`（`name` / `size` / `modified`）和 `order_direction`（`asc` / `desc`）。排序遵循 115 接口语义，并非对整个目录做 AList 本地自然排序。

隐藏规则、角色权限始终在返回前检查。页面缓存保留原始页，过滤是每请求执行的，不共享某用户的过滤结果。刷新、写操作和挂载更新会让旧页失效。

- 前端仓库：`https://github.com/AlistGo/alist-web.git`
- 固定版本：`907756a8d5dff27d6b73036734de0a6533ace553`
- `solid-router` 子模块：`f77b206e8592bb56d2d001e9488de5a54a13699b`
- 改动文件：`web-patches/115-on-demand.patch`

补丁在这个后端 fork 内携带，不要求再 fork 前端仓库。`scripts/build-paged-web.sh` 在临时目录检出上述固定版本、应用补丁，测试/构建成功后才写入 `public/dist`。

**不要直接用原 `build.sh` 的 Web 下载步骤生成这个版本。** 它下载的是未修改前端，会覆盖配套 UI。应使用下面的专用工作流。仅替换后端而保留旧“全部”模式前端，可能只看到第一页且没有翻页按钮。

## 安全验证和打包

当前源码仍为待验证版本；最近这一轮按要求没有运行构建、测试编译、竞态检查或依赖安装。不能沿用早前限流补丁的成功结果声称本次完整分页改动已通过。

面向 `main` 的 PR 创建、更新后，GitHub Actions 的 **115 on-demand pagination (PR and manual)** 自动执行以下验证；合并后也可从默认分支手动触发：

1. 本地模拟的后端分页/权限/缓存测试。
2. 后端相关竞态检查。
3. 固定版本配套前端及离线测试。
4. 将配套 UI 嵌入 Linux amd64 后端并上传实验性产物及 SHA256 校验。

此工作流使用 `pull_request` 和 `workflow_dispatch`，无需先合并分页代码就能在 PR 中验证。它只在 GitHub 托管机器上运行，权限为 `contents: read`，不发布、不部署。Go 测试和前端构建串行执行；工作流不读取你的 AList 数据、Cookie 或真实 115 账号。本机不执行这些构建。

本地前端构建脚本默认拒绝执行；即使显式允许，也要求至少 3 GiB 可用 RAM，容器内存上限至少 4 GiB，不将 Swap 算作安全余量。Node 堆上限不是整个进程组的内存上限，不能据此在小内存线上服务器构建。

部署前备份原程序和数据，核对 `dist_dir` / 静态资源 CDN 不会加载旧 UI，再单独测试。当前运行中的 AList 未被修改、重启或替换。

## 已知边界

- 仅直接挂载的 **115 Cloud** 启用上游分页；115 Open、分享和未实现分页能力的旧驱动保持原行为。
- WebDAV、目录选择器 `/fs/dirs`、索引及显式完整列表调用仍可能遍历全目录；逐请求限速仍保留。别名、加密等包装驱动暂不转发分页能力。
- 分页目录内有其他虚拟挂载时明确返回不支持，不悄悄退回全量读取。建议将这些挂载放在独立父目录。
- “文件夹置底”无法在现有上游范围内可靠模拟，明确报错；关闭该选项或使用文件夹置顶。
- 文件详情不再拉全目录寻找相关文件，目录外字幕/相关文件自动发现能力受到限制。
- 名称映射可能不可逆；已浏览页面会保留原始名称。冷链接含无法确定的映射时提示先打开父目录页面，不猜测、不扫描所有页。
- 文件冷链接查询只读取最多 50 条候选；目标可能位于更多候选中时返回明确的“有歧义 / 先打开父目录页面”错误，不伪装成文件不存在，不继续扫描。
- 按页缓存与对象提示随进程结束丢失；外部客户端修改后的可见性遵循缓存有效期或显式刷新。限速/冷却按挂载共享，并非同账号所有客户端共享。
- 本补丁不能保证永不触发 115 风控，也不能解除已有风控。
